## 1. Введение: Декомпозиция ИИ-агента

Представьте, что вы смотрите на самый совершенный автомобиль. Снаружи — блестящий корпус, элегантные линии, тонированные стекла. Он движется быстро, плавно и, кажется, понимает каждое ваше желание. Для обывателя это — магия. Но для инженера — это симфония работающих вместе систем: двигателя, трансмиссии, подвески, электроники. Каждая деталь имеет свое место и свою функцию.

С ИИ-агентами — точно так же. Для многих они до сих пор остаются «черным ящиком», который каким-то волшебным образом отвечает на вопросы, ищет информацию и даже пишет код. Но магии здесь нет. Есть инженерное искусство. ИИ-агент — это не монолитный сверхразум, а тщательно спроектированная архитектура, состоящая из отдельных, но тесно связанных компонентов.

В этой главе мы проведем полную **декомпозицию ИИ-агента на его ключевые составляющие**. Мы разберем его на винтики, чтобы понять, как он устроен, как «думает» и почему способен выполнять сложные задачи, недоступные простой LLM.

### Почему это критически важно для вас?

Потому что только поняв архитектуру, вы сможете:
- Создавать понастоящему мощных и уникальных агентов, а не просто использовать готовые шаблоны из фреймворков
- Эффективно отлаживать и оптимизировать их работу, точно зная, какой компонент дал сбой или требует улучшения
- Контролировать затраты, понимая, на что тратятся драгоценные токены API
- Обеспечивать безопасность, осознавая, где находятся потенциальные уязвимости

## 2. Компонент 1: Мозг (LLM) - Центральный процессор

**LLM (Large Language Model)** — это **ядро и центральная нервная система** нашего агента. Это не просто один из компонентов; это **ядро**, вокруг которого строится вся остальная архитектура. Без LLМ агент был бы просто набором скриптов, неспособным к адаптации и «разумному» поведению.

### Функции LLM в контексте агента:

1. **Понимание цели и рассуждение (Reasoning)**: Когда вы даете агенту высокого уровня задачу, например, «Проанализируй последние финансовые новости компании N и сделай вывод о ее перспективах», именно LLM первой вступает в игру. Она парсит ваш запрос на естественном языке, выделяет ключевые сущности и, что самое главное, **рассуждает** о том, как эту задачу можно решить. Это больше не генерация ответа, а формирование стратегии.

2. **Выбор инструмента (Tool Selection)**: LLM сама по себе «слепа и глуха» к реальному миру. Она не имеет доступа к интернету, файловой системе или базам данных. Ее знания ограничены датой последнего обновления датасета, на котором она обучалась. И здесь в игру вступают Инструменты. Мозг-LLM, проанализировав задачу, решает, **какой "мускул"** нужно задействовать.

Примеры:
- Задача «Какой сегодня курс доллара?» → LLM решает: «Мне нужен инструмент для поиска в интернете».
- Задача «Посчитай 25% от 1573» → LLM решает: «Мне нужен инструмент-калькулятор, потому что я могу ошибиться в арифметике».
- Задача «Найди email Джона Смита в файле contacts.csv» → LLM решает: «Мне нужен инструмент для чтения CSV-файлов».

3. **Синтез информации (Information Synthesis)**: После того как инструменты выполнили свою работу и вернули «сырые» данные, LLM снова берет на себя роль главного аналитика. Она обрабатывает эту информацию, отсеивает шум, извлекает суть и формирует из разрозненных фрагментов единый, осмысленный ответ, соответствующий изначальной цели.

### Ограничения LLM и почему они формируют архитектуру

Именно **ограничения LLM** заставляют нас строить вокруг нее сложную обвязку из других компонентов:

1. **Отсутствие актуальных знаний**: Модель не знает о событиях, произошедших после ее обучения. Это делает **Инструменты** (например, поиск в Google) жизненно необходимыми.

2. **Отсутствие прямого взаимодействия с миром**: LLM не может сама запустить код, прочитать файл или отправить API-запрос. Для этого ей нужны **Инструменты**.

3. **Ограниченное окно контекста**: LLM может «помнить» лишь определенный объем текста. Все, что не помещается в это окно, она «забывает». Это порождает необходимость в **Памяти**.

4. **Склонность к «галлюцинациям»**: Иногда LLM может выдумывать факты. Использование **Инструментов** для верификации информации — один из способов борьбы с этим.

### Пример принятия решения LLM

Давайте посмотрим на упрощенный пример того, как LLM может выступать в роли «диспетчера»:

```python
import openai

def choose_tool(user_query: str) -> str:
    """
    Использует LLM, чтобы решить, какой инструмент использовать для ответа на запрос пользователя.
    """
    # Это специальный промпт, который "заставляет" LLM думать как диспетчер.
    # Мы даем ей описание доступных инструментов и просим выбрать один.
    system_prompt = """
    Ты — ИИ-диспетчер. Твоя задача — проанализировать запрос пользователя и выбрать один из следующих инструментов для его выполнения:
    - 'search_engine': для поиска актуальной информации в интернете, новостей, фактов.
    - 'calculator': для выполнения математических вычислений.
    - 'file_reader': для чтения содержимого локальных файлов.
    - 'general_conversation': если запрос не требует специальных инструментов и на него можно ответить общими знаниями.
    
    В своем ответе укажи ТОЛЬКО название инструмента и ничего больше.
    Пример:
    Пользователь: Какой рост у Эйфелевой башни?
    Ответ: search_engine
    """

    try:
        response = openai.chat.completions.create(
            model="gpt-3.5-turbo",  # Или gpt-4, claude-3-opus и т.д.
            messages=[
                {"role": "system", "content": system_prompt},
                {"role": "user", "content": user_query}
            ],
            temperature=0.0,  # Нам нужен детерминированный, а не творческий ответ
            max_tokens=10
        )

        tool_name = response.choices[0].message.content.strip()
        return tool_name
    except Exception as e:
        print(f"Произошла ошибка при вызове API: {e}")
        return "error"

# --- Тестируем нашего диспетчера ---
query1 = "Сколько будет 345 * 12.5?"
query2 = "Кто стал победителем последнего чемпионата мира по футболу?"
query3 = "Расскажи мне анекдот про программиста."

print(f"Запрос: '{query1}' -> Выбранный инструмент: {choose_tool(query1)}")
print(f"Запрос: '{query2}' -> Выбранный инструмент: {choose_tool(query2)}")
print(f"Запрос: '{query3}' -> Выбранный инструмент: {choose_tool(query3)}")

# Ожидаемый вывод:
# Запрос: 'Сколько будет 345 * 34.5?' -> Выбранный инструмент: calculator
# Запрос: 'Кто стал победителем последнего чемпионата мира по футболу?' -> Выбранный инструмент: search_engine
# Запрос: 'Расскажи мне анекдот про программиста.' -> Выбранный инструмент: general_conversation
```

Этот простой пример — квинтэссенция роли LLM в агенте. Мы не просим ее выполнить задачу, мы просим **ее принять решение о том, как задача должна быть выполнена**. Это фундаментальный сдвиг парадигмы, который и лежит в основе всей архитектуры ИИ-агентов. Мозг-LLM — это не исполнитель, а **дирижер оркестра** из Инструментов, Памяти и Планировщика.

## 3. Компонент 2: Инструменты (Tools) - Руки и глаза агента

Если LLM — это мозг, то **Инструменты (Tools)** — это **все остальное**: руки, ноги, глаза, уши и даже голос. Это мост, который соединяет абстрактные рассуждения языковой модели с конкретной реальностью — будь то интернет, ваша файловая система или API стороннего сервиса. Без инструментов агент — это гениальный, но парализованный мыслитель, запертый в цифровой комнате.

### Что такое инструмент в контексте ИИ-агента?

**Инструмент** — это **любая функция или API**, которую агент может вызвать для получения информации или выполнения действия во внешнем мире.

Ключевое здесь — «вызвать». Агент не просто знает о существовании Google, он может активно использовать его поисковый API. Он не просто знает синтаксис SQL, он может выполнить запрос к реальной базе данных.

Инструменты — это то, что превращает агента из «всезнайки» в «всеумейку».

### Категории инструментов:

1. **Инструменты для поиска информации**:
   - Веб-поиск: Интеграция с API Google, Bing, DuckDuckGo для получения свежей информации
   - Специализированные поисковики: Поиск по научным статьям, новостям, документации
   - Поиск по базам знаний: Интеграция с Wikipedia, Wolfram|Alpha

2. **Инструменты для работы с данными**:
   - Python REPL: Возможность выполнять произвольный код на Python
   - SQL-клиент: Способность подключаться к базам данных и выполнять SQL-запросы
   - Работа с файлами: Чтение и запись различных форматов

3. **Инструменты для взаимодействия с внешними системами**:
   - Вызов произвольных API: Это суперсила! Агент может управлять вашими задачами в Jira, отправлять сообщения в Slack
   - Управление браузером: Использование библиотек вроде Selenium или Playwright
   - Работа с командной строкой

### Как это работает технически: Магия описаний

Как LLM, которая умеет работать только с текстом, может «вызвать» функцию на Python? Ответ кроется в гениальной простоте этого механизма.

**1. Описание (Description)**: Для каждого инструмента мы создаем текстовое описание (часто в виде docstring в Python), которое объясняет LLM, что этот инструмент делает, какие аргументы он принимает и в каком формате.

**2. Передача описаний в промпт**: Когда агент начинает работу, мы передаем LLM в системном промпте список всех доступных ей инструментов с их описаниями.

**3. Генерация вызова**: LLM, решив, что ей нужен определенный инструмент, генерирует не сам код, а специальным образом отформатированную строку или JSON-объект, который содержит:
   - Имя инструмента, который нужно вызвать
   - Аргументы для этого инструмента

**4. Парсинг и исполнение**: Управляющий код агента (его «цикл исполнения») перехватывает этот вывод от LLM, парсит его, находит нужную функцию в коде и вызывает ее с указанными аргументами.

**5. Возврат результата**: Результат работы функции снова преобразуется в текст и отправляется обратно в LLM для дальнейшего анализа.

### Пример инструмента на Python

```python
def calculator(expression: str) -> str:
    """
    Очень полезный инструмент, когда нужно выполнить математическое вычисление.
    Принимает на вход строку с математическим выражением (например, "2 + 2 * 10").
    Возвращает результат вычисления в виде строки.
    Используй этот инструмент для любой математики, не пытайся считать в уме.
    """
    try:
        # ВНИМАНИЕ: eval() - это очень небезопасно для продакшена!
        # Мы используем его здесь только для демонстрации.
        # В реальных приложениях нужно использовать безопасные парсеры выражений.
        result = eval(expression, {"__builtins__": {}}, {})
        return str(result)
    except Exception as e:
        return f"Ошибка вычисления: {e}"

# --- Как агент будет это использовать ---
# 1. LLM получает промпт, в котором есть описание функции calculator.
#    Промпт: "Ты — ИИ-ассистент. У тебя есть инструмент `calculator`.
#    Описание: `Очень полезный инструмент...` 
#    Задача: Посчитай, сколько будет, если от 1000 отнять 35*4."

# 2. LLM рассуждает (про себя): "Так, мне нужно посчитать 35*4, а потом отнять от 1000.
#    Это математика. Мне нужно использовать инструмент `calculator`."

# 3. LLM генерирует специальный вывод, например, в формате JSON:
llm_output = '{"tool_name": "calculator", "arguments": {"expression": "1000 - (35 * 4)"}}'

# 4. Наш код парсит этот JSON:
import json
call_data = json.loads(llm_output)
tool_name = call_data['tool_name']
arguments = call_data['arguments']

# 5. Наш код находит и вызывает нужную функцию:
if tool_name == "calculator":
    # ** - это распаковка словаря в именованные аргументы
    result = calculator(**arguments)
    print(f"Результат от инструмента: {result}")

# Результат: Результат от инструмента: 860
```

Ключевой вывод: инструменты — это **API для LLM**. Они определяют границы возможного для вашего агента. Хотите, чтобы агент работал с вашим корпоративным софтом? Напишите для него инструмент-обертку над API этого софта. Хотите, чтобы он анализировал биржевые данные? Дайте ему инструмент для их получения. Ваша фантазия (и навыки программирования) — единственное ограничение.

## 4. Компонент 3: Память - От золотой рыбки до слона

Представьте разговор с человеком, который каждые 30 секунд забывает все, что вы ему сказали. Бессмысленно и утомительно, не так ли? Именно так вела бы себя LLM без механизма памяти. Как мы уже знаем, у языковых моделей есть «окно контекста» — ограниченный объем информации, который они могут удерживать одномоментно. Все, что выходит за его пределы, бесследно исчезает.

Память (Memory) в архитектуре ИИ-агента — это компонент, который **решает эту проблему**. Она позволяет агенту сохранять, извлекать и использовать информацию из предыдущих взаимодействий, превращая разрозненные обмены репликами в осмысленный, продолжительный диалог или рабочий процесс.

### Типы памяти:

**1. Краткосрочная (оперативная) память**:
- Как работает: Вся история текущего диалога просто добавляется в промпт при каждом новом обращении к LLM.
- Преимущества: Простота реализации, высокая точность
- Недостатки: Стоимость, ограничение по размеру, скорость

**2. Долгосрочная память**:
- Основана на векторных базах данных (ChromaDB, FAISS) и эмбеддингах
- Позволяет агенту накапливать знания и извлекать только релевантную информацию
- Практика: Загрузка документов → Разбиение на чанки → Создание эмбеддингов → Поиск по сходству → Использование извлеченной информации

Архитектура памяти агента строится по схожему принципу с человеческим мозгом:
- Краткосрочная память: то, о чем мы думаем прямо сейчас
- Долгосрочная память: наши знания, опыт, воспоминания

## 5. Компонент 4: Планировщик - Внутренний стратег

Мы дали нашему агенту мозг (LLM), руки и глаза (Инструменты) и память. Но как заставить все это работать вместе для достижения сложной, многошаговой цели?

Если я попрошу вас «организовать мне ужин с друзьями в центре Москвы в эту субботу», вы не броситесь сразу звонить в первый попавшийся ресторан. Вы начнете **планировать**:
1. Уточнить количество друзей
2. Определить бюджет
3. Выяснить предпочтения по кухне
4. Найти в интернете подходящие рестораны
5. Проверить отзывы
6. Позвонить и забронировать столик
7. Сообщить всем место и время

**Планировщик (Planner)** — это компонент, который отвечает за этот процесс. Это часто не отдельный кусок кода, а **специальный режим работы самой LLM**, который активируется с помощью хитрого промпт-инжиниринга.

### Зачем нужен планировщик?

- **Декомпозиция**: Сложные задачи почти невозможно решить за один шаг
- **Оптимизация**: План позволяет выбрать наиболее эффективную последовательность действий
- **Устойчивость к ошибкам**: Если один из шагов плана провалился, агент может попытаться выполнить следующий шаг или скорректировать план
- **Прозрачность**: Глядя на сгенерированный план, мы можем понять "логику" агента

### Как работает планирование?

1. **Получение цели**: Агент получает от пользователя сложную задачу
2. **Вызов Планировщика**: Агент обращается к LLM со специальным промптом
3. **Генерация Плана**: LLM генерирует план в виде текста или структурированных данных (JSON, YAML)
4. **Исполнение Плана**: Агент начинает выполнять шаги плана один за другим, используя Цикл Исполнения

## 6. Компонент 5: Цикл Исполнения и паттерн ReAct

**Цикл Исполнения** — это **сердце агента**, его главный рабочий процесс. Это бесконечный (до достижения цели) цикл, который координирует работу всех остальных компонентов.

Современные агенты используют **паттерн ReAct** (Reason + Act) — философия, которая предлагает модели сначала **рассуждать вслух** (генерировать текст с рассуждениями), а потом **действовать** (выбирать инструмент).

### Цикл ReAct состоит из трех фаз:

1. **Мышль (Thought)**: Агент анализирует текущую ситуацию и генерирует текст, описывающий его внутренний монолог
2. **Действие (Action)**: На основе своей "мысли" агент выбирает конкретный Инструмент
3. **Наблюдение (Observation)**: Агент выполняет Действие и получает результат — это Наблюдение

Этот цикл **Мысль → Действие → Наблюдение** повторяется снова и снова. Наблюдение с предыдущего шага становится частью входных данных для генерации Мысли на следующем шаге.

### Пример работы цикла ReAct

Задача: «Кто является режиссером фильма, в котором снимался актер, сыгравший главную роль в "Матрице"?»

**Итерация 1**:
- Входная цель: «Кто является режиссером фильма, в котором снимался актер, сыгравший главную роль в "Матрице"?»
- **Мысль 1**: Окей, это многосоставной вопрос. Сначала мне нужно выяснить, кто играл главную роль в фильме "Матрица".
- **Действие 1**: `search_engine(query="актер главной роли в фильме Матрица")`
- **Наблюдение 1**: «Главную роль Нео в фильме "Матрица" сыграл Киану Ривз»

**Итерация 2**:
- Входные данные: (Изначальная цель + Наблюдение 1)
- **Мысль 2**: Отлично, теперь я знаю, что актер — Киану Ривз. Следующий шаг — найти фильм, о котором идет речь в вопросе...
- **Действие 2**: `search_engine(query="режиссер фильма Матрица")`
- **Наблюдение 2**: «Режиссерами и сценаристами фильма "Матрица" являются Лана и Лилли Вачовски»

**Итерация 3**:
- Входные данные: (Изначальная цель + Наблюдение 1 + Наблюдение 2)
- **Мысль 3**: Я нашел актера (Киану Ривз) и режиссеров ("Вачовски"). Я соединил все части вопроса. Теперь у меня есть окончательный ответ.
- **Действие 3**: `finish(answer="Режиссерами фильма 'Матрица', где главную роль сыграл Киану Ривз, являются сестры Вачовски (Лана и Лилли).")`

### Почему ReAct так эффективен?

- **Прозрачность и отладка**: Читая последовательность "мыслей" агента, мы можем пошагово отследить его логику
- **Самокоррекция**: Если Действие приводит к ошибке, агент "видит" эту ошибку в своей "мысли" и может предпринять корректирующее действие
- **Надежность**: Заставляя LLM сначала рассуждать, а потом действовать, мы значительно снижаем вероятность ошибок

## 7. Практическая реализация архитектуры

Теперь давайте реализуем простую, но полную архитектуру ИИ-агента на Python, объединяя все изученные компоненты:

```python
import json
import requests
from typing import Dict, Any, List

class SimpleAgent:
    """
    Простой ИИ-агент с основными компонентами:
    - Мозг (условно представлен через вызовы API)
    - Инструменты
    - Память (очень простая)
    - Цикл ReAct
    """
    
    def __init__(self):
        self.memory = []
        self.tools = {
            'web_search': self.web_search,
            'calculator': self.calculator
        }
    
    def web_search(self, query: str) -> str:
        """
        Простой инструмент для поиска в интернете (в реальности использовал бы API)
        """
        # В реальности это будет вызов SerpAPI, Google Search API и т.д.
        return f"Результаты поиска для запроса '{query}': [список результатов]"
    
    def calculator(self, expression: str) -> str:
        """
        Инструмент для математических вычислений
        """
        try:
            # Простой безопасный калькулятор
            allowed_chars = set('0123456789+-*/(). ')
            if not all(c in allowed_chars for c in expression):
                return "Ошибка: недопустимые символы в выражении"
            
            # В реальности использовался бы более безопасный парсер
            result = eval(expression)
            return str(result)
        except Exception as e:
            return f"Ошибка вычисления: {str(e)}"
    
    def think(self, goal: str, available_tools: List[str]) -> Dict[str, Any]:
        """
        Симуляция "мышления" LLM
        """
        # В реальности это будет вызов LLM с промптом, содержащим цель и список инструментов
        # Пока что просто симулируем логику выбора
        if "сколько будет" in goal.lower() or "посчитай" in goal.lower():
            return {
                "thought": f"Это математическая задача. Я буду использовать калькулятор.",
                "action": {
                    "tool_name": "calculator",
                    "arguments": {"expression": goal.split("посчитай ")[-1] if "посчитай" in goal else goal.split("сколько будет ")[-1]}
                }
            }
        elif "найди" in goal.lower() or "поищи" in goal.lower():
            return {
                "thought": f"Мне нужно найти информацию в интернете.",
                "action": {
                    "tool_name": "web_search",
                    "arguments": {"query": goal.split("найди ")[-1] if "найди" in goal else goal.split("поищи ")[-1]}
                }
            }
        else:
            return {
                "thought": "Я не уверен, какой инструмент использовать, поэтому просто отвечу.",
                "action": {
                    "tool_name": None,
                    "arguments": {}
                }
            }
    
    def execute_action(self, action: Dict[str, Any]) -> str:
        """
        Выполнение выбранного действия
        """
        tool_name = action.get("tool_name")
        arguments = action.get("arguments", {})
        
        if tool_name and tool_name in self.tools:
            result = self.tools[tool_name](**arguments)
            return result
        else:
            return "Нет доступного инструмента для выполнения."
    
    def run(self, goal: str) -> str:
        """
        Основной цикл работы агента (ReAct)
        """
        iteration = 0
        max_iterations = 5  # Ограничение, чтобы избежать бесконечного цикла
        
        current_goal = goal
        
        while iteration < max_iterations:
            iteration += 1
            print(f"\n--- Итерация {iteration} ---")
            
            # 1. Мышление
            decision = self.think(current_goal, list(self.tools.keys()))
            print(f"Мысль: {decision['thought']}")
            
            # Сохраняем мысль в памяти
            self.memory.append({"type": "thought", "content": decision["thought"]})
            
            # 2. Действие
            action = decision["action"]
            if action["tool_name"]:
                print(f"Действие: вызов инструмента '{action['tool_name']}' с аргументами {action['arguments']}")
                result = self.execute_action(action)
                
                # Сохраняем результат в памяти
                self.memory.append({"type": "result", "tool": action["tool_name"], "content": result})
                
                print(f"Результат: {result}")
                
                # 3. Наблюдение - используем результат для корректировки дальнейших действий
                current_goal = f"Предыдущий результат: {result}. Как мне продвигаться к цели: {goal}?"
            else:
                # Если нет инструмента, значит цель достигнута или нужен прямой ответ
                return decision["thought"]
        
        return f"Максимальное количество итераций ({max_iterations}) достигнуто. Последний результат: {result if 'result' in locals() else 'Нет результата'}"

# Пример использования
if __name__ == "__main__":
    agent = SimpleAgent()
    
    # Пример 1: Математическая задача
    result1 = agent.run("Посчитай сколько будет 25 * 4 + 10")
    print(f"\nРезультат 1: {result1}")
    
    # Сбрасываем память для нового задания
    agent.memory = []
    
    # Пример 2: Поиск в интернете
    result2 = agent.run("Найди кто написал роман Война и Мир")
    print(f"\nРезультат 2: {result2}")
```

## 8. Заключение: От чертежей к сборке

Мы только что провели полную анатомическую разборку ИИ-агента. Мы увидели, что за кажущейся магией скрывается **элегантная и логичная инженерная система**. Это больше не «черный ящик», а понятная вам архитектура.

**Давайте еще раз закрепим ключевые роли**:
- **LLM (Мозг)**: Принимает решения, рассуждает и синтезирует информацию. Это центр управления полетами.
- **Инструменты (Мускулы)**: Выполняют конкретные действия в реальном мире. Это исполнительные механизмы.
- **Память (Опыт)**: Позволяет агенту учиться и сохранять контекст. Это его личный архив.
- **Планировщик (Стратег)**: Разбивает большие цели на маленькие, достижимые шаги. Это его внутренний project-менеджер.
- **Цикл ReAct (Сердце)**: Заставляет все компоненты работать в унисон, обеспечивая динамику, адаптивность и самокоррекцию. Это двигатель, который приводит все в движение.

Понимание этой декомпозиции — ваш **фундамент**. Это то, что отличает простого пользователя фреймворков от настоящего архитектора интеллектуальных систем. Вы теперь знаете «что» и «зачем». Вы видите не просто код, а живой организм, который можно и нужно настраивать, улучшать и адаптировать под свои задачи.

Мир не стоит на месте. Колесо автоматизации, которое когда-то заменило ткачей и конюхов, сейчас делает свой очередной, куда более стремительный поворот. ИИ-агенты уже сегодня начинают брать на себя рутинные интеллектуальные задачи. Игнорировать это — значит добровольно остаться на обочине истории. Понять, как они устроены изнутри — значит оседлать эту волну и стать тем, кто будет формировать будущее.
