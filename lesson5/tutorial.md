## 1. Введение: Почему инструменты — это суперсила ИИ-агента

До этого момента наши агенты были немногословны. Они понимали язык, рассуждали, планировали, но у них не было "рук" и "глаз", чтобы взаимодействовать с реальным миром. Большие языковые модели (LLM), такие как GPT-4, Claude 3 или Llama 3, по своей сути являются невероятно сложными системами для предсказания следующего слова в последовательности. Они обучены на гигантских объемах текста и кода, что позволяет им вести осмысленный диалог, писать стихи, генерировать код и обобщать информацию. Но у них есть фундаментальные ограничения:

1. **Слепота к реальному времени**: Знания LLM ограничены датой среза их обучающих данных. Они не знают, кто выиграл вчерашний матч или какой сегодня курс доллара.
2. **Изоляция от окружения**: Модель не имеет прямого доступа к вашей файловой системе, базам данных или внутренним API вашей компании.
3. **Ненадежность в фактах и расчетах**: LLM может «галлюцинировать» — уверенно выдавать ложную информацию. Спросите у нее, чему равно 17917 * 1483, и она может выдать очень правдоподобный, но неверный ответ.

**Инструменты решают все три проблемы.** Они выступают в роли моста между изолированным "мозгом" LLM и внешним миром. Вспомните архитектуру ReAct (Reason + Act), которую мы обсуждали ранее. Инструменты — это и есть та самая часть «Act» (Действие).

### Агентский цикл выглядит так:
1. **Reason (Рассуждение)**: LLM анализирует задачу и имеющийся контекст. Она решает, что для следующего шага ей не хватает информации или нужно выполнить какое-то действие. Она формулирует мысль: "Чтобы ответить на вопрос о текущей цене акций "ТехноКорп", мне нужно поискать эту информацию в интернете".
2. **Act (Действие)**: LLM генерирует вызов конкретного инструмента с нужными аргументами. Например, `google_search(query="текущая цена акций ТехноКорп")`.
3. **Observation (Наблюдение)**: Наша программа на Python исполняет этот вызов, получает результат (например, строку с ценой акции с финансового сайта) и передает его обратно в контекст агента.
4. **Повторение цикла**: Теперь у LLM есть новый фрагмент информации. Она снова рассуждает (Reason) и решает, что делать дальше: ответить пользователю, использовать другой инструмент или продолжить исследование.

Без инструментов агент — это просто чат-бот. С инструментами он становится автономной сущностью, способной к активному взаимодействию с цифровой средой. Именно в этот момент, когда агент получает инструменты, он начинает "думать" и "действовать".

## 3. Практика: Создание инструмента для поиска в Google на Python

### Шаг 1: Установка библиотеки и получение API-ключа

Самый надежный и профессиональный подход для поиска в Google — использовать специализированные API, такие как SerpAPI. Он берет на себя всю грязную работу по обходу блокировок и парсингу результатов, а вам отдает чистый и структурированный JSON.

Установим официальную Python-библиотеку от SerpAPI:
```bash
pip install google-search-results
```

Зарегистрируйтесь на сайте serpapi.com и получите свой личный API Key. Сохраните его в переменных окружения.

### Шаг 2: Написание функции-обертки

```python
import os
from serpapi import GoogleSearch

def google_search(query: str) -> str:
    """
    Выполняет поиск в Google по заданному запросу (query) с использованием SerpAPI
    и возвращает краткую сводку результатов.
    
    Этот инструмент предназначен для использования ИИ-агентом, чтобы получать
    актуальную информацию из интернета.
    
    Args:
        query (str): Поисковый запрос, который необходимо выполнить.
    
    Returns:
        str: Строка с обобщенными результатами поиска (например, основной ответ,
        если он есть, и заголовки нескольких первых ссылок) или сообщение
        об ошибке.
    """
    try:
        # Получаем ключ из переменных окружения
        api_key = os.environ.get("SERPAPI_API_KEY")
        if not api_key:
            return "Ошибка: API-ключ SerpAPI не найден в переменных окружения."
        
        # Формируем параметры запроса
        params = {
            "q": query,
            "api_key": api_key,
            "engine": "google",
            "gl": "ru",  # Геолокация для получения результатов на русском
            "hl": "ru",  # Язык интерфейса
        }
        
        search = GoogleSearch(params)
        results = search.get_dict()
        
        # Обрабатываем и упрощаем результат для LLM
        summary = []
        
        # "Answer Box": Если Google выдал прямой ответ на вопрос
        if "answer_box" in results and "answer" in results["answer_box"]:
            summary.append(f"Основной ответ: {results['answer_box']['answer']}")
        elif "answer_box" in results and "snippet" in results["answer_box"]:
            summary.append(f"Основной ответ: {results['answer_box']['snippet']}")
        
        # Органическая выдача: берем заголовки и сниппеты первых 3 результатов
        if "organic_results" in results:
            summary.append("Основные результаты:")
            for i, result in enumerate(results["organic_results"][:3]):  # Берем первые 3 результата
                summary.append(f"{i+1}. {result['title']}: {result.get('snippet', 'Нет описания')}")
        
        if not summary:
            return f"По запросу '{query}' ничего не найдено."
            
        return "\n".join(summary)
    
    except Exception as e:
        # Логируем полную ошибку для отладки, но агенту возвращаем простое сообщение
        print(f"Произошла ошибка при поиске: {e}")
        return "Ошибка при выполнении поиска. Попробуйте переформулировать запрос."
```

**Разбор полетов**:
1. **Четкая сигнатура и документация**: Функция имеет аннотацию типов и подробный docstring — критически важно для агента.
2. **Безопасное получение ключа**: Используем `os.environ.get()` — стандартная практика.
3. **Формирование запроса**: Указываем параметры геолокации и языка для получения релевантных результатов.
4. **Парсинг и упрощение результата**: Передаем в LLM только суть, а не весь объемный JSON.
5. **Надежная обработка исключений**: Агент не упадет с ошибкой, а получит внятное сообщение.

## 4. Практика: Инструмент для чтения локальных файлов

Часто агенту нужно работать с информацией, которая уже есть на локальной машине.

### Шаг 1: Написание функции-инструмента

```python
import os

def read_file(filepath: str) -> str:
    """
    Безопасно читает содержимое текстового файла по указанному пути (filepath).
    
    Этот инструмент предназначен для использования ИИ-агентом для чтения
    локальных файлов, предоставленных пользователем.
    В целях безопасности, он проверяет существование файла перед чтением
    и ограничен чтением только текстовых файлов.
    
    Args:
        filepath (str): Путь к файлу, который необходимо прочитать.
                        Должен быть абсолютным или относительным от текущей рабочей директории.
    
    Returns:
        str: Содержимое файла в виде строки, если чтение успешно.
             В противном случае - строка с сообщением об ошибке.
    """
    # ВАЖНАЯ ПРОВЕРКА БЕЗОПАСНОСТИ:
    # Ограничиваем доступ агента только определенной "песочницей"
    allowed_directory = os.path.abspath("./agent_workspace")
    requested_path = os.path.abspath(filepath)
    
    if not requested_path.startswith(allowed_directory):
        return f"Ошибка безопасности: доступ к файлу '{filepath}' запрещен. "\ 
               f"Разрешено чтение только из директории '{allowed_directory}'."
    
    if not os.path.exists(filepath):
        return f"Ошибка: файл по пути '{filepath}' не найден."
    
    try:
        with open(filepath, 'r', encoding='utf-8') as f:
            content = f.read()
        
        # Обрезаем контент, чтобы не перегружать LLM большим количеством токенов
        max_chars = 4000
        if len(content) > max_chars:
            return content[:max_chars] + "\n... (файл был обрезан)"
        
        return content
    
    except UnicodeDecodeError:
        return f"Ошибка: не удалось прочитать файл '{filepath}' как текстовый " \
               "(UTF-8). Возможно, это бинарный файл."
    except Exception as e:
        print(f"Произошла непредвиденная ошибка при чтении файла: {e}")
        return f"Ошибка при чтении файла '{filepath}': {str(e)}"
```

**Ключевые аспекты безопасности**:
1. **Ограничение директории ("Песочница")**: Проверка `requested_path.startswith(allowed_directory)` — жесткое ограничение доступа.
2. **Проверка существования файла**: `os.path.exists()` предотвращает падение с ошибкой.
3. **Контекстный менеджер `with open()`**: Гарантирует корректное закрытие файла.
4. **Указание кодировки**: `encoding='utf-8'` — стандарт для текстовых файлов.
5. **Обрезание контента**: Предотвращает отправку слишком больших объемов текста в LLM.

## 5. Практика: Простой инструмент-калькулятор

Многомиллиардные языковые модели, способные рассуждать о философии и писать код, часто ошибаются в умножении или делении. Дать агенту инструмент-калькулятор — это как выдать бухгалтеру калькулятор вместо счетов.

**Опасный путь: функция `eval()`**
```python
# НЕ ДЕЛАЙТЕ ТАК В РЕАЛЬНОМ КОДЕ ДЛЯ АГЕНТА!
def unsafe_calculator(expression: str):
    return eval(expression)

# Агент может сгенерировать такой вызов:
unsafe_calculator("5 * (10 + 3)")  # Вернет 65, все хорошо

# Но он может сгенерировать и такой:
unsafe_calculator("__import__('os').system('rm -rf /')")  # Катастрофа!
```

Функция `eval()` выполняет любую переданную ей строку как код Python. Это гигантская дыра в безопасности.

**Безопасная альтернатива**:
```python
import re
import operator

def safe_calculator(expression: str) -> str:
    """
    Безопасно вычисляет простое арифметическое выражение.
    Поддерживает операции: +, -, *, /.
    Не исполняет произвольный код, в отличие от eval().
    
    Args:
        expression (str): Строка с математическим выражением, например "10 + 5".
    
    Returns:
        str: Результат вычисления или сообщение об ошибке.
    """
    # Шаг 1: Валидация ввода. Разрешаем только цифры, точки, пробелы и операторы.
    if not re.match(r"^[0-9\.\s\+\-\*\/\(\)]*$", expression):
        return "Ошибка: выражение содержит недопустимые символы."
    
    # Шаг 2: Безопасное вычисление.
    # Более безопасный подход: написать свой простой парсер
    # или использовать специализированную библиотеку вроде 'numexpr'.
    
    # Здесь мы используем более надежную библиотеку ast.literal_eval для
    # основных арифметических операций.
    
    try:
        # Упрощенный парсер для выражений вида "число оператор число"
        ops = {
            '+': operator.add,
            '-': operator.sub,
            '*': operator.mul,
            '/': operator.truediv
        }
        
        # Разбиваем выражение (для простого случая)
        parts = expression.split()
        if len(parts) == 3:  # Только простые выражения
            num1 = float(parts[0])
            op = parts[1]
            num2 = float(parts[2])
            
            if op in ops:
                result = ops[op](num1, num2)
                return str(result)
        else:
            # Если выражение сложнее, возвращаем ошибку
            return "Ошибка: поддерживаются только простые выражения вида 'число оператор число', например '5 * 10'."
    
    except ValueError:
        return "Ошибка: не удалось преобразовать части выражения в числа."
    except ZeroDivisionError:
        return "Ошибка: деление на ноль."
    except Exception as e:
        return f"Произошла ошибка при вычислении: {e}"

    # Важное примечание: Представленный выше парсер умышленно сделан очень 
    # простым ("число оператор число"). Он не поддерживает скобки или 
    # сложную последовательность операций. В реальном проекте для 
    # вычисления математических выражений от LLM стоит 
    # использовать специализированные библиотеки, такие как numexpr, 
    # которая выполняет вычисления быстро и безопасно, не используя eval.
```

## 6. Интеграция инструментов с логикой ИИ-агента

Теперь самый главный вопрос: как заставить агента понять, что у него есть эти инструменты, и научить его ими пользоваться?

**Ответ кроется в промпт-инжиниринге.** Мы должны описать доступные инструменты в системном промпте (system prompt) или в специальной части основного промпта.

LLM лучше всего работает со **структурированными данными**. Поэтому мы опишем каждый наш инструмент в виде, похожем на JSON или YAML. Этот формат должен включать:

- **tool_name**: Имя функции, которую нужно вызвать.
- **description**: Человекочитаемое описание того, что делает инструмент. Именно его будет читать LLM, чтобы решить, подходит ли этот инструмент для текущей подзадачи.
- **arguments**: Словарь, описывающий параметры, которые принимает функция.

**Пример системного промпта с описанием инструментов**:
```python

1. **Мысль**: Сначала подумай, какой следующий шаг нужно сделать для достижения цели.
```

## 7. Реализация цикла агента на Python

```python
    for i in range(max_turns):
        print(f"\n--- ИТЕРАЦИЯ {i+1} ---")
        
        prompt_for_llm = f"{SYSTEM_PROMPT}\n\nИстория диалога и действий:\n{history}"
        llm_output_str = call_llm(prompt_for_llm)
        
        # Извлекаем JSON из ответа LLM (он может быть в блоке ```json ... ```)
        try:
            # Убираем "обертку" для JSON
            json_str = llm_output_str.strip().lstrip("```json").rstrip("```").strip()
            llm_response = json.loads(json_str)
            print("--- ОТВЕТ LLM ---\n", json.dumps(llm_response, indent=2, ensure_ascii=False))
        except json.JSONDecodeError:
            print("Ошибка: LLM вернула невалидный JSON. Прерывание.")
            history += "\nСистемная ошибка: не удалось распознать твой ответ."
            continue  # Позволяем агенту исправиться в следующей итерации
        
        if "action" in llm_response:
            action = llm_response["action"]
            tool_name = action["tool_name"]
            arguments = action["arguments"]
            
            if tool_name in TOOL_REGISTRY:
                tool_function = TOOL_REGISTRY[tool_name]
                # Вызываем инструмент
                try:
                    observation = tool_function(**arguments)
                    print(f"--- РЕЗУЛЬТАТ ИНСТРУМЕНТА ({tool_name}) ---\n{observation}")
                except TypeError as e:
                    observation = f"Ошибка: Неверные аргументы для инструмента '{tool_name}'. {e}"
                except Exception as e:
                    observation = f"Ошибка выполнения инструмента '{tool_name}': {e}"
                    
                history += f"\nМысль: {llm_response['thought']}\n" \
                           f"Действие: Вызов {tool_name} с аргументами {arguments}\n" \
                           f"Наблюдение: {observation}"
            else:
                history += f"\nНаблюдение: Ошибка, ты попытался вызвать несуществующий инструмент '{tool_name}'."
        
        elif "final_answer" in llm_response:
            print("\n--- ФИНАЛЬНЫЙ ОТВЕТ АГЕНТА ---")
            print(llm_response["final_answer"])
            return
        
    print("\nАгент достиг максимального числа итераций.")
```

Этот цикл — **сердце нашего агента**. Он методично подает LLM всю необходимую информацию, получает от неё команду, исполняет её с помощью наших Python-функций и передает результат обратно. Это и есть магия автономных агентов в действии.

## 8. Безопасность инструментов: Как не дать агенту "сжечь дом"

Мы уже касались безопасности при создании каждого инструмента, но эту тему необходимо выделить в отдельный, самый важный раздел. Когда вы даете агенту инструменты, вы даете ему **власть**. Власть читать файлы, искать в интернете, тратить деньги на API-вызовы и, если вы не будете осторожны, выполнять произвольный код.

**Управление этой властью — ваша главная задача как разработчика.** Вот многоуровневая стратегия защиты:

### Уровень 1: Санкционирование (Whitelisting)
**Принцип**: Агент должен иметь доступ только к тем инструментам, которые ему абсолютно необходимы для выполнения задачи.
- Не передавайте в промпт описания всех существующих у вас инструментов
- Создавайте разные "наборы инструментов" для разных типов агентов

### Уровень 2: Валидация ввода
**Принцип**: Никогда не доверяйте данным, сгенерированным LLM. Всегда проверяйте и очищайте аргументы, прежде чем передать их в функцию-инструмент.
- Используйте Pydantic для строгой валидации
- Проверяйте содержимое параметров (как мы делали в `safe_calculator` и `read_file`)

### Уровень 3: Ограничение прав и Песочница (Sandboxing)
**Принцип**: Код, который исполняет агент (особенно если у него есть инструмент для выполнения Python-кода), должен работать в изолированной среде.
- Простая песочница: Ограничение доступа к файловой системе
- Docker-контейнеры: Запуск кода, сгенерированного агентом, внутри изолированного контейнера

### Уровень 4: Человеческий контроль (Human-in-the-Loop)
**Принцип**: Для любых критически важных, необратимых или дорогостоящих действий требуется подтверждение человека.
- Удаление файлов: Запрос подтверждения перед выполнением
- Отправка сообщений: Показывать текст агента вам на утверждение

**Безопасность — это не то, что можно добавить в конце.** Это образ мышления, который должен пронизывать каждый этап разработки вашего ИИ-агента.

### LangChain

```python
# Создаем инструмент с помощью декоратора
@tool
def search_finance_data(ticker: str) -> str:
    """Поиск финансовой информации по тикеру акции."""
    # Ваша реализация
    return f"Financial data for {ticker}:..."

# Или создаем инструмент вручную
python_repl = PythonREPL()
python_tool = Tool(
    name="python_repl",
    description="Выполняет Python код и возвращает результат",
    func=python_repl.run
)

# Список инструментов передается в агента
tools = [search_finance_data, python_tool]
```

В этой главе мы совершили гигантский скачок. Наш агент перестал быть теоретиком и получил возможность действовать. Мы своими руками создали для него три базовых, но жизненно важных инструмента: `google_search`, `read_file`, и `safe_calculator`.

Мы поняли, что **инструменты — это мультипликатор силы LLM**, компенсирующий её врожденные слабости: оторванность от реальности и неточность в расчетах. Мы разобрали, как с помощью грамотного промпт-инжиниринга и структурированного описания «объяснить» агенту, какими возможностями он теперь обладает.

Мы создали элегантный цикл на Python, который дирижирует этим сложным оркестром из мыслей, действий и наблюдений. И, самое главное, мы заложили фундамент ответственной разработки — постоянно повторяли мантру безопасности: санкционирование, валидация, изоляция и человеческий контроль.

Мы научились давать своему ИИ руки и глаза. Но пока он страдает **амнезией** — каждая итерация цикла для него начинается почти с чистого листа, за исключением краткой истории диалога. Чтобы он мог учиться на своем опыте, запоминать факты и строить долгосрочные планы, ему нужна **память**.

Именно об этом мы и поговорим в следующих главах. Мы перейдем от базовой контекстной памяти к созданию настоящей долговременной памяти с помощью векторных баз данных, превратив нашего агента из способного исполнителя в по-настоящему умного ассистента.
