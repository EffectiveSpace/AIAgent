## 1. Введение: Промпт как душа машины

Представьте, что вы наняли на работу гения. Он обладает доступом ко всем знаниям человечества, способен анализировать, писать код, творить и считать с молниеносной скоростью. Но есть нюанс: у него синдром дефицита внимания, помноженный на бесконечность. Без четких, кристально ясных инструкций он будет либо сидеть, глядя в стену, либо займется чем-то совершенно не тем — например, вместо анализа квартального отчета начнет писать сонеты о бренности бытия.

**Добро пожаловать в мир больших языковых моделей (LLM)**. Это и есть наш "гений", и промпт-инжиниринг — это умение давать ему правильные инструкции.

### Почему промпт — это пульт управления, а не просто вопрос?

Для простого чат-бота вроде ChatGPT промпт — это разовый запрос. Вы спросили, он ответил. Диалог окончен. 

Для ИИ-агента **системный промпт (system prompt)** — это его **конституция, его ДНК, его базовый набор правил**, к которому он возвращается на каждом шаге своего мыслительного цикла.

Вспомним архитектуру ReAct из предыдущей главы. Агент постоянно находится в цикле:
1. **Мысль (Thought)**: Анализ текущей ситуации и цели
2. **Действие (Action)**: Выбор инструмента и его запуск  
3. **Наблюдение (Observation)**: Получение результата от инструмента

**Именно промпт диктует**, как агент должен думать, какие действия он может совершать и как ему интерпретировать наблюдения.

## 2. Анатомия идеального промпта: Системные шаблоны для агентов

Любой мощный системный промпт для агента состоит из нескольких **логических блоков**. Представьте, что вы собираете его из конструктора.

### 1. [РОЛЬ/ПЕРСОНА]
**Цель**: Задать контекст и личность. Модели вроде GPT-4 и Claude 3 отлично умеют "вживаться в роль".

**Пример**:
```
Ты — старший финансовый аналитик в инвестиционной компании "ТехноФинанс".
```

### 2. [ГЛОБАЛЬНАЯ ЦЕЛЬ]
**Цель**: Четко определить конечную задачу, к которой агент должен стремиться.

**Пример**:
```
Твоя основная цель — помогать клиентам принимать обоснованные инвестиционные решения, анализируя рынок, составляя отчеты и отвечая на вопросы.
```

### 3. [ИНСТРУМЕНТЫ]
**Цель**: Предоставить LLM точное описание инструментов, которые она может использовать.

**Пример**:
```
Ты имеешь доступ к следующим инструментам:
- `search_web(query: str)`: Используй для поиска актуальной информации в интернете
- `analyze_stock(symbol: str)`: Получи информацию об акции по тикеру
- `finish_task(final_answer: str)`: Используй, когда полностью ответишь на запрос пользователя
```

### 4. [ПРОЦЕСС/МЫСЛИТЕЛЬНЫЙ ЦИКЛ]
**Цель**: Объяснить модели, как именно она должна думать и действовать.

**Пример**:
```
Ты работаешь в цикле "Мысль -> Действие":
1. **Мысль**: Кратко анализируй цель пользователя и текущую ситуацию. Определи, какое действие принесет максимальную пользу.
2. **Действие**: Выбери ОДИН инструмент из доступных и сформируй для него вызов в формате JSON.
```

### 5. [ФОРМАТ ВЫВОДА]
**Цель**: Задать строгий формат, в котором модель должна вернуть свой ответ.

**Пример**:
```
Ты ДОЛЖНА отвечать в формате JSON:
{
  "thought": "Твоя внутренняя мысль",
  "action": {
    "tool_name": "имя_инструмента",
    "parameters": { ... }
  }
}
```

### 6. [ОГРАНИЧЕНИЯ И ПРАВИЛА]
**Цель**: Установить "красные флажки" и важные правила поведения.

**Пример**:
```
Ограничения:
- Никогда не придумывай новые инструменты
- Не отвечай на вопросы о политике или религии
- Если не уверен в информации, скажи "Я не уверен"
```

## 3. Шаблон №1: Промпт для Планирования (The Architect’s Blueprint)

Некоторые сложные задачи требуют предварительной декомпозиции. Вместо того чтобы сразу бросаться в цикл "Мысль-Действие", мы можем сначала попросить модель составить план.

**Цель**: Разбить одну большую и неясную цель на последовательность конкретных, проверяемых шагов.

**Шаблон промпта для планирования**:
```
Ты — эксперт по планированию задач. Твоя задача — разбить сложную пользовательскую цель на серию простых, выполнимых шагов.

Доступные инструменты: {available_tools_description}

Пользовательская цель: {user_goal}

Инструкции:
1. Проанализируй цель пользователя.
2. Подумай о логической последовательности действий, которые приведут к цели, используя ТОЛЬКО доступные инструменты.
3. Декомпозируй цель в список шагов.

Ответь в формате JSON:
{
  "plan": [
    "Шаг 1: [описание действия]",
    "Шаг 2: [описание действия]",
    ...
  ]
}
```

**Пример**:
```
Пользовательская цель: "Найти информацию о погоде в Москве и Санкт-Петербурге и сохранить в файл"

Возможный план:
{
  "plan": [
    "1. Найти текущую погоду в Москве",
    "2. Найти текущую погоду в Санкт-Петербурге", 
    "3. Сравнить данные",
    "4. Сохранить результат в файл 'weather_comparison.txt'"
  ]
}
```

## 4. Шаблон №2: Промпт для Действия (The Operator’s Command)

Это основной рабочий промпт для агента, работающего по циклу ReAct. Он выполняется на каждом шаге.

**Цель**: На основе всей предыдущей истории (цели, плана, прошлых действий и наблюдений) сгенерировать следующую пару "Мысль" и "Действие".

**Полный шаблон**:
```
Ты — автономный ИИ-агент "{agent_name}", способный достигать сложных целей.

Ты работаешь в цикле "Мысль-Действие-Наблюдение".

**РОЛЬ**: Ты — {agent_role}
**ЦЕЛЬ**: {user_goal}

**ДОСТУПНЫЕ ИНСТРУМЕНТЫ**:
{tools_description}

**ПРАВИЛА**:
- Всегда думай, прежде чем действовать
- Используй только перечисленные инструменты
- Если инструмент возвращает ошибку, проанализируй ошибку и попробуй альтернативный подход

**ФОРМАТ ВЫВОДА**:
Ты ДОЛЖНА отвечать исключительно в формате JSON:
{
  "thought": "Твоя внутренняя мысль, анализирующая текущую ситуацию и следующий шаг",
  "action": {
    "tool_name": "имя_инструмента_из_списка",
    "parameters": {
      "имя_параметра": "значение"
    }
  }
}

После каждого действия ты получишь "Наблюдение" с результатом. Используй его для следующей "Мысли".

НАЧАТЬ.
```

## 5. Шаблон №3: Промпт для Анализа и Рефлексии (The Strategist’s Debrief)

Иногда агент заходит в тупик. Инструмент вернул ошибку, поиск не дал результатов, план оказался неверным. В этот момент можно использовать специальный промпт для "рефлексии".

**Цель**: Заставить модель проанализировать свои предыдущие действия, выявить ошибку и предложить скорректированный план действий.

**Шаблон промпта для рефлексии**:
```
Ты — модуль анализа и рефлексии. Твоя задача — проанализировать работу другого агента и предложить улучшения.

**Оригинальная цель**: {original_goal}
**История выполнения**: {execution_history}
**Последнее наблюдение/ошибка**: {last_observation_error}

Проанализируй:
1. Что пошло не так?
2. Был ли план изначально неверен?
3. Был ли выбран неправильный инструмент?
4. Были ли ошибки в логике?

Предложи:
1. Новый план действий или корректировку существующего
2. Альтернативные подходы
3. Как избежать подобных ошибок в будущем

Ответь в формате JSON:
{
  "analysis": "Анализ проблемы и причин",
  "recommendation": "Рекомендация по исправлению"
}
```

## 6. Техники продвинутого промптинга: Заставляем LLM думать глубже

Шаблоны — это скелет. Но чтобы наделить нашего агента настоящей сообразительностью, нам нужны техники, которые **стимулируют более сложные когнитивные процессы** внутри LLM. Две самые известные и мощные из них — Chain-of-Thought и Tree-of-Thought.

### Chain-of-Thought (CoT): Рассуждай вслух

**Проблема**: Когда мы просим LLM решить сложную задачу одним махом, она пытается сгенерировать ответ напрямую. Если задача требует нескольких логических шагов, модель может легко ошибиться, пропустив один из них.

**Решение**: Техника **Chain-of-Thought** заключается в том, чтобы **явно попросить модель "думать вслух"** или "рассуждать по шагам" перед тем, как дать финальный ответ.

**Пример БЕЗ CoT**:
```
Запрос: "У Маши было 5 яблок. Она отдала 2 яблока Пете, а потом купила еще 3. Сколько яблок у нее стало?"
Ответ: У Маши стало 6 яблок. (Неверно: 5 - 2 + 3 = 6, но правильный ответ 6)
```

**Пример С CoT**:
```
Запрос: "У Маши было 5 яблок. Она отдала 2 яблока Пете, а потом купила еще 3. Сколько яблок у нее стало? Рассуждай по шагам."
Ответ:
1. Изначально у Маши было 5 яблок.
2. Она отдала 2 яблока, значит, у нее осталось 5 - 2 = 3 яблока.
3. Затем она купила еще 3 яблока, значит, у нее стало 3 + 3 = 6 яблок.
**Ответ: 6 яблок.**
```

Видите? Во втором случае модель сама себя поправила в процессе рассуждения.

**Включение CoT в промпт агента**:
```python
# В поле "thought" агента будет реализован CoT
{
  "thought": "Для решения задачи X я должен: 1) выполнить действие A, 2) проанализировать результат B, 3) принять решение C. Я начну с действия A, потому что...",
  "action": {...}
}
```

### Tree-of-Thought (ToT): Древо Мыслей для сложных задач

**Проблема**: CoT — это одна, линейная цепочка рассуждений. А что, если на каком-то шаге есть несколько равновероятных путей? Или если первоначальный путь рассуждений оказался тупиковым?

**Решение**: **Tree-of-Thought** — это более продвинутый подход. Он предлагает модели **исследовать не одну, а несколько возможных цепочек рассуждений** (ветвей дерева), оценивать их перспективность и выбирать лучшую.

**Как работает ToT**:
1. **Декомпозиция**: Модель разбивает проблему на шаги
2. **Генерация мыслей**: На каждом шаге LLM генерирует не одну, а несколько (3-5) возможных следующих мыслей
3. **Оценка мыслей**: Другой вызов LLM оценивает каждую из этих мыслей по шкале "перспективности"
4. **Выбор и исследование**: Агент выбирает лучшую мысль и продолжает "дерево" рассуждений от нее

**Пример**:
Задача: "Какой инвестиционный портфель выбрать для новичка с $10,000?"

ToT рассмотрит несколько подходов:
- Консервативный (90% облигации, 10% акции)
- Умеренный (70% акции, 30% облигации) 
- Агрессивный (95% акции, 5% облигации)

Затем оценит каждый и выберет лучший.

**Применение в агентских промптах**:
ToT реализуется не в одном промпте, а в **архитектуре** с множественными вызовами LLM и управлением "ветвлением" из кода.

```python
def search_web(query: str) -> str:

    """
```

### Шаг 3: Пишем Python-оркестратор
```python
# main_agent.py
import os
import json
from openai import OpenAI
from tools import search_web
from system_prompt import SYSTEM_PROMPT

# Настройка
client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))
MODEL_NAME = "gpt-4-turbo-preview"

def run_agent(user_request: str):
    """
    Запускает ИИ-агента для выполнения запроса пользователя.
    """
    print(f"🚀 Агент запущен с задачей: {user_request}\n")
    
    # Инициализируем историю сообщений
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": user_request}
    ]
    
    # Доступные инструменты
    available_tools = {
        "search_web": search_web,
        # В реальности finish_tool просто завершает цикл
    }
    
    turn_count = 1
    max_turns = 10  # Ограничитель, чтобы не уйти в бесконечный цикл
    
    while turn_count <= max_turns:
        print(f"--- 🔄 Ход {turn_count} ---")
        
        # 1. Отправляем запрос в LLM
        response = client.chat.completions.create(
            model=MODEL_NAME,
            messages=messages,
            response_format={"type": "json_object"}  # Важно для стабильного получения JSON
        )
        
        response_message = response.choices[0].message
        messages.append(response_message)  # Добавляем ответ LLM в историю
        print(f"🧠 Ответ LLM: {response_message.content[:100]}...")
        
        # 2. Парсим JSON ответа
        try:
            parsed_response = json.loads(response_message.content)
            thought = parsed_response.get("thought")
            action = parsed_response.get("action")
            print(f"🤔 Мысль: {thought[:100] if thought else 'Нет мысли'}...")
            
            # 3. Выполняем действие
            if action:
                tool_name = action.get("tool_name")
                tool_params = action.get("arguments")
                
                if tool_name == "finish_task":
                    final_answer = tool_params.get("final_answer")
                    print(f"\n✅ Агент завершил работу с ответом:\n{final_answer}")
                    return final_answer
                    
                elif tool_name in available_tools:
                    # Вызываем функцию инструмента
                    tool_function = available_tools[tool_name]
                    try:
                        observation = tool_function(**tool_params)
                        print(f"🔍 Результат: {observation[:100]}...")
                        
                        # Добавляем результат в историю для следующего хода
                        messages.append({
                            "role": "user", 
                            "content": f"Наблюдение: {observation}"
                        })
                    except Exception as e:
                        error_msg = f"Ошибка выполнения инструмента {tool_name}: {e}"
                        print(f"❌ {error_msg}")
                        messages.append({"role": "user", "content": f"Ошибка: {error_msg}"})
                else:
                    error_msg = f"Неизвестный инструмент: {tool_name}"
                    print(f"⚠️ {error_msg}")
                    messages.append({"role": "user", "content": f"Ошибка: {error_msg}"})
            else:
                print("❌ В ответе LLM отсутствует 'action'.")
                break
                
        except (json.JSONDecodeError, AttributeError) as e:
            print(f"❌ Ошибка парсинга ответа LLM: {e}")
            print(f"Полученный ответ: {response_message.content}")
            break
            
        turn_count += 1
        print("-" * 20)
    
    if turn_count > max_turns:
        print(f"\n⚠️ Достигнут лимит ходов ({max_turns}). Агент остановлен.")
    
    return "Агент не завершил задачу в отведенное количество итераций"
```

## 8. Заключение: Промпт как душа машины

В этой главе мы прошли путь от абстрактного понимания промптинга до создания конкретного, рабочего кода. Мы увидели, что **промпт для агента — это не просто текст, а сложная инженерная конструкция**, определяющая его поведение, возможности и даже "характер".

### Ключевые выводы:
1. **Структура решает всё**: Хороший системный промпт, разделенный на блоки (Роль, Цель, Инструменты, Правила, Формат) — это 90% успеха в создании предсказуемого агента
2. **Шаблоны — наши чертежи**: Использование готовых шаблонов для планирования, действий и рефлексии значительно ускоряет разработку
3. **Мышление можно стимулировать**: Техники вроде Chain-of-Thought (которую мы встроили в поле `thought`) кардинально повышают качество рассуждений LLM
4. **Практика — критерий истины**: Только написав код и увидев, как агент выполняет цикл ReAct вживую, можно по-настоящему понять всю магию и мощь этого подхода

Вы теперь обладаете фундаментальным навыком — **умением вести диалог с искусственным разумом на его языке**. Вы можете давать ему инструкции, и он будет их выполнять. Но пока наш агент слеп и глух к реальному миру, кроме той информации, что мы ему подсовываем через фейковые функции. У него нет настоящих «рук».
