# Lesson 8: Планирование и автономия: Создание автономного ИИ-агента на Python

## Цели урока

После изучения этого урока вы сможете:

- Применить паттерн ReAct (Reason + Act) для построения цикла мышления и действия

## 1. Введение: От инструкций к намерениям

Представьте себе двух работников. 
- Первому вы даете пошаговую инструкцию: «Возьми отчёт за Q3 из папки Y, скопируй колонку "Продажи", вставь её в шаблон Z, отправь результат на почту боссу». Он выполнит это безупречно. Но если папка Y окажется пустой или шаблон Z будет повреждён, работа встанет. Он — идеальный исполнитель, но не более.
- Второму: «Подготовь и отправь боссу отчёт по продажам за Q3». Он сам найдёт нужный отчёт, заметит, что шаблон повреждён, найдёт прошлый шаблон, адаптирует его, и если продажи оказались необычно низкими, пришлёт дополнительно пояснительную записку.

**Второй — это автономный агент.** Это разница между получением инструкции и пониманием намерения.

### Почему планирование — это скачок к автономии?

До сих пор наши агенты работали в основном в **реактивном режиме**: мы даём команду → агент подбирает инструмент → выполняет действие → возвращает результат. Это мощно, но фундаментально ограничено. Такой агент похож на GPS-навигатор, который может подсказать только следующий поворот, но не видит всей карты и не способен перестроить маршрут, если впереди пробка.

**Планирование — это и есть та самая "карта".** Это способность агента, получив высокоуровневую цель, не бросаться сразу выполнять первое попавшееся действие, а сначала составить внутренний план — последовательность шагов, которые, по его мнению, приведут к желаемому результату.

**Архитектура планирования**:
```
Пользовательская цель -> [ПЛАНИРОВЩИК] -> План (список подзадач) -> [ЦИКЛ ВЫПОЛНЕНИЯ] -> Результат
```

Планирование превращает нашего агента из простого **«исполнителя функций»** (function-caller) в **«решателя проблем»** (problem-solver). Это фундаментальный сдвиг в парадигме, который и открывает дорогу к настоящей, полезной автономии ИИ.

## 2. Искусство декомпозиции: Как научить агента "кушать слона по частям"

«Как съесть слона? По кусочку». Эта старая шутка — идеальное описание процесса **декомпозиции задач**. Это первый и самый важный этап планирования. Большая языковая модель (LLM) благодаря своим возможностям понимания языка и построения логических цепочек идеально подходит на роль **декомпозировщика**.

Наша задача — с помощью правильного **промпт-инжиниринга** заставить модель взять большую цель и **разбить ее на маленькие, конкретные и выполнимые шаги**. Существует несколько ключевых подходов к этому.

### 1. Chain-of-Thought (CoT): Линейное мышление

**Chain-of-Thought (Цепочка Мыслей)** — это простейшая, но невероятно эффективная техника. Мы просим модель не просто дать ответ, а **"подумать вслух"**, расписав шаги, которые привели её к этому ответу. Этот подход заставляет LLM активировать свои "рассуждательные" способности и генерировать более логичные и последовательные планы.

**Пример простого промпта для декомпозиции с CoT**:
```
Ты — умный планировщик задач. Твоя цель — разбить сложную задачу на простые, последовательные шаги.
Подумай шаг за шагом, как достичь следующей цели.

Цель: "Написать обзорную статью о влиянии технологии 5G на индустрию IoT (Интернета вещей)".
Твои шаги:
```

**Ожидаемый ответ от LLM (например, GPT-4)**:
```
1. Сбор базовой информации: Сначала нужно понять основы. Я найду и изучу общие статьи о том, что такое 5G и что такое IoT, чтобы определить ключевые характеристики каждой технологии.
2. Поиск точек пересечения: Далее я сфокусируюсь на том, как преимущества 5G (высокая скорость, низкая задержка, большое количество подключений) решают проблемы IoT (перегрузка сетей, задержки в передаче данных от датчиков).
3. Исследование конкретных примеров (Use Cases): Я найду реальные примеры применения 5G в IoT. Например: "умные" города (управление трафиком), промышленный IoT (IIoT, предиктивное обслуживание оборудования), подключенные автомобили (V2X), телемедицина (удаленные операции).
4. Анализ преимуществ и вызовов: Собрав информацию, я структурирую её. Я выделю ключевые преимущества (например, возможность обработки данных в реальном времени) и вызовы (например, стоимость внедрения, вопросы безопасности).
5. Структурирование статьи: На основе собранной информации я создам структуру статьи: Введение, Основная часть (как 5G улучшает IoT, примеры по отраслям), Аналитический раздел (преимущества и проблемы), Заключение (будущее 5G и IoT).
6. Написание текста статьи: Финальный шаг — написать текст статьи, следуя разработанной структуре и используя собранную информацию.
```

Как видите, вместо туманной цели у нас появился **четкий, линейный план действий**. Каждый шаг можно превратить в конкретную задачу для агента (например, `search("преимущества 5G для IoT")`).

### 2. Tree-of-Thought (ToT): Параллельное и ветвящееся мышление

**Tree-of-Thought (Дерево Мыслей)** — это более продвинутый и мощный подход. Если **CoT — это одна, линейная цепочка рассуждений**, то **ToT — это исследование сразу нескольких возможных "тропинок"**, оценка каждой из них и выбор наилучшей.

Этот метод особенно полезен, когда задача имеет **несколько возможных путей решения** или когда **высока вероятность зайти в тупик**.

**Как работает ToT на концептуальном уровне**:
1. **Декомпозиция на мысли**: Агент генерирует не одну, а **несколько** возможных следующих шагов (или мыслей).
   - Цель: «Инвестировать $1000 в акции технологических компаний».
   - Мысль 1: «Проанализировать акции "большой пятерки" (FAANG)».
   - Мысль 2: «Найти перспективные, но недооцененные стартапы в области ИИ».
   - Мысль 3: «Изучить ETF-фонды, сфокусированные на технологическом секторе».
2. **Оценка мыслей**: Агент (или отдельный "оценочный" модуль) оценивает каждую мысль по шкале "перспективности".
   - Оценка Мысли 1: «Надежно, но потенциал роста умеренный».
   - Оценка Мысли 2: «Высокий риск, но огромный потенциал роста».
   - Оценка Мысли 3: «Сбалансированный подход, диверсификация рисков».
3. **Исследование (Exploration)**: Агент выбирает наиболее перспективные ветки (например, 1 и 3) и делает следующий шаг в каждой из них, снова генерируя несколько вариантов. Так строится "дерево" рассуждений.
4. **Выбор лучшего пути**: В конце агент, используя эвристики или поиск, находит наиболее полную и успешную цепочку мыслей от корня до листа и принимает её за финальный план.

Real-world implementation of ToT is significantly more complex than CoT and often requires sophisticated orchestration (like with frameworks such as LangGraph) that manages multiple LLM calls for generation, evaluation, and selection. For complex, creative or strategic tasks, this approach yields much higher quality planning than linear CoT. The key insight is that CoT (in the form of `thought` field in our agents) is our foundation, but ToT represents the potential for agents to think in parallel and branch, exploring multiple solution paths.

## 3. Паттерн ReAct: "Мысль-Действие-Наблюдение" в коде

Итак, у нас есть план, разбитый на шаги. Как заставить агента его выполнять? Просто передать весь список шагов инструментам? Нет. Мир изменчив. Первый же шаг может дать неожиданный результат, который сделает весь остальной план бессмысленным.

Здесь на сцену выходит **ReAct (Reason + Act)** — элегантная и мощная парадигма, которая объединяет рассуждение и действие в единый итеративный цикл. ReAct был предложен исследователями из Google Brain и быстро стал **де-факто стандартом для автономных агентов**.

**Суть ReAct** заключается в трех шагах, которые повторяются снова и снова, пока цель не будет достигнута:

1. **Thought (Мысль)**: Агент анализирует текущую цель, предыдущие шаги и их результаты. На основе этого он решает, что делать дальше. Это **внутренний монолог LLM**, где она рассуждает о стратегии.

2. **Action (Действие)**: На основе "мысли" агент выбирает конкретный инструмент и параметры для его вызова. Например, `search("ключевые игроки на рынке электромобилей 2025")` или `write_file("preliminary_report.txt", "...")`.

3. **Observation (Наблюдение)**: Агент выполняет действие и получает результат (или ошибку). Это может быть текст с веб-страницы, ответ от API, сообщение об успехе записи файла или код ошибки.

Этот результат (Observation) подается на вход следующей итерации цикла, и агент снова начинает с "мысли" (Thought), но уже с учетом новой информации.

**Почему этот цикл так эффективен?**
- **Адаптивность**: Агент не слепо следует плану. Он постоянно сверяется с реальностью (через Observation) и корректирует свои дальнейшие шаги.
- **Прозрачность**: Мы видим "мысли" агента. Это бесценно для отладки. Мы можем понять, почему он решил сделать то или иное действие.
- **Управляемость**: Мы можем вмешиваться в этот цикл, например, добавляя правила в промпт, которые направляют "мысли" агента в нужное русло.

### Пример промпта для агента, работающего по циклу ReAct

Самое важное в реализации ReAct — это системный промпт, который объясняет модели правила игры.

```
Ты — автономный ИИ-агент, способный достигать сложных целей.

Ты работаешь в цикле "Мысль-Действие-Наблюдение".

На каждом шаге ты должен сгенерировать блок "Мысль", в котором ты рассуждаешь о том, что нужно сделать для достижения цели.

Затем ты должен сгенерировать блок "Действие", который представляет собой вызов одного из доступных тебе инструментов в формате JSON.

После каждого действия ты получишь "Наблюдение" с результатом, которое ты должен использовать для следующей "Мысли".

Продолжай, пока не достигнешь конечной цели. Когда цель достигнута, твоим последним действием должно быть `{"tool_name": "finish", "args": {"answer": "Твой финальный ответ"}}`.

ДОСТУПНЫЕ ИНСТРУМЕНТЫ:
1. `web_search`:
   - Описание: Ищет информацию в интернете.
   - Аргументы: `{"query": "текст твоего запроса"}`

2. `write_file`:
   - Описание: Записывает текст в файл.
   - Аргументы: `{"filename": "имя_файла.txt", "content": "содержимое файла"}`

3. `finish`:
   - Описание: Завершает работу и возвращает финальный ответ.
   - Аргументы: `{"answer": "итоговый результат твоей работы"}`

НАЧНЕМ!

Цель: "Создать файл report.txt с кратким обзором трех главных преимуществ языка программирования Python."
```

### Пример работы цикла ReAct

Допустим, агент получает задачу: "Создать файл report.txt с кратким обзором трех главных преимуществ Python".

**Итерация 1:**
Агент (LLM) генерирует:
```json
{
  "thought": "Отлично, я получил всю необходимую информацию. Я выделил три ключевых преимущества: 1. Простота и читаемость. 2. Огромная экосистема библиотек. 3. Сильное сообщество. Теперь мне нужно записать это в файл `report.txt`, как и требовалось в цели.",
  "action": {
    "tool_name": "write_file",
    "args": {
      "filename": "report.txt",
      "content": "Три главных преимущества Python:\n1. Простота синтаксиса и высокая читаемость кода.\n2. Обширная стандартная библиотека и экосистема сторонних пакетов для любых задач.\n3. Большое и активное сообщество, предоставляющее поддержку и ресурсы."
    }
  }
}
```

Наша система (Python-код):
1. Парсит этот JSON.
2. Видит `action.tool_name == "write_file"`.
3. Вызывает нашу функцию `write_file("report.txt", "...содержимое...")`.
4. Функция возвращает результат (успешно записано).

**Итерация 2:**
Наша система передает в LLM всю историю:
```
... (начальный промпт) ...
Цель: "Создать файл report.txt с кратким обзором трех главных преимуществ языка программирования Python."
Прошлые шаги:
Действие: `write_file` с содержимым "Три главных преимущества Python:..."
Наблюдение: "Файл report.txt успешно записан."
Твой следующий шаг (Мысль и Действие):
```

Агент (LLM) генерирует:
```json
{
  "thought": "Я успешно создал файл report.txt с требуемой информацией. Моя задача выполнена.",
  "action": {
    "tool_name": "finish",
    "args": {
      "answer": "Файл report.txt с обзором преимуществ Python создан успешно."
    }
  }
}
```

И цикл завершается!

Этот простой, но мощный цикл — **основа, на которой мы будем строить нашего автономного агента**.

## 4. "Что-то пошло не так": Обработка ошибок и гибкое перепланирование

Мир — хаотичное место. API падают, сайты меняют верстку, инструменты возвращают неожиданные результаты, а иногда первоначальный план LLM оказывается неверным. Агент, который "ломается" от первой же ошибки, бесполезен в реальных задачах. **Отказоустойчивость** — это не дополнительная фича, а обязательное требование.

Ключевая идея здесь — **самокоррекция (self-correction)**. Мы должны дать агенту возможность не просто узнать об ошибке, но и проанализировать её и принять решение, как действовать дальше.

### Классификация ошибок

**1. Технические ошибки (Уровень инструмента)**:
- Сетевые ошибки: API недоступен (ошибка 503), тайм-аут запроса
- Ошибки доступа: Неверный API-ключ (ошибка 401/403)
- Ошибки выполнения: Инструмент не смог обработать входные данные

**Как обрабатывать**: Обернуть вызовы инструментов в `try...except`. Если происходит ошибка, мы не прерываем работу агента, а передаем ему информацию об ошибке в поле `Observation`.

**2. Логические ошибки (Уровень планирования)**:
- Агент ищет информацию, но использует неверные ключевые слова
- Агент пытается проанализировать данные, которых еще не собрал
- Агент зацикливается, повторяя одно и то же действие

**Как обрабатывать**: Явно указать агенту на возможность того, что его план может быть неверным, и поощрять рефлексию и перепланирование:
```
...
ВАЖНО: Если ты видишь, что твои действия не приближают тебя к цели, или если ты получаешь бесполезные результаты, остановись и подумай. В своей "Мысли" явно укажи, что первоначальный план не работает, и предложи новый план. Не бойся менять стратегию. Твоя главная задача — достичь конечной цели, а не слепо следовать первоначальному плану.
...
```

**3. Галлюцинации и неправильные факты**:
LLM могут выдумывать факты или неверно интерпретировать информацию.

**Как обрабатывать**:
- **Строгая валидация**: Наш Python-код должен быть "привратником". Прежде чем выполнить действие, сгенерированное LLM, мы должны проверить:
  - Существует ли инструмент с таким именем?
  - Соответствуют ли переданные аргументы сигнатуре этого инструмента?
- **Обратная связь**: Если валидация не пройдена, мы возвращаем в `Observation` четкое сообщение об ошибке.

## 5. Практика: Создание автономного агента-исследователя

Тепура. Мы находимся у истоков технологии, которая лежит в основе нового поколения чат-ботов, корпоративных поисковых систем и персональных ассистентов. Но память — лишь один из столпов истинной автономии. Агент, который помнит всё, но не умеет самостоятельно ставить цели и планировать свои действия, — это всего лишь очень умная база данных.

Именно поэтому в следующих главах мы перейдем к самому сердцу автономии — **планированию и автономии**. Мы научим нашего агента **decomposing сложных целей** на последовательность конкретных шагов, **реагировать на ошибки** и **адаптировать свой план на лету**. Мы внедрим механизмы **обратной связи и самокоррекции**, которые превращают наших агентов из простых исполнителей в **по-настоящему мыслящих субъектов**.

До этого момента наши агенты были вроде умных калькуляторов, отвечающих на вопросы. В следующей главе они превратятся в **действующих лиц**, способных **самостоятельно достигать целей**.

### Задача для агента
"Проанализировать текущее состояние рынка автономных ИИ-агентов на 2025 год. Выделить 3 ключевых фреймворка, их основные преимущества и сохранить результат в файл 'ai_agents_market_2025.txt'."

### Шаг 1: Настройка

```python
# tools.py
import json

def web_search(query: str) -> str:
    """Имитирует поиск в интернете. Возвращает заранее подготовленные данные."""
    print(f"--- ИНСТРУМЕНТ: Поиск по запросу: '{query}' ---")
    
    # "База знаний" нашего "игрушечного" интернета
    knowledge_base = {
```

### Шаг 3: Основной цикл агента

```python
# agent.py
import os
import json
from openai import OpenAI
from prompts import get_system_prompt
from tools import AVAILABLE_TOOLS

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

class AutonomousAgent:
    def __init__(self, goal):
        self.goal = goal
        self.history = []
        self.system_prompt = get_system_prompt()
    
    def run(self, max_iterations=10):
        print(f"🎯 ЦЕЛЬ АГЕНТА: {self.goal}\n" + "="*50)
        
        for i in range(max_iterations):
            print(f"\n--- ИТЕРАЦИЯ {i+1} ---\n")
            
            # Формируем промпт для LLM, включая историю
            messages = [
                {"role": "system", "content": self.system_prompt},
                {"role": "user", "content": f"Цель: {self.goal}\n\nИстория предыдущих шагов:\n{self._format_history()}"}
            ]
            
            # Вызов LLM
            try:
                response = client.chat.completions.create(
                    model="gpt-4-turbo-preview",
                    messages=messages,
                    response_format={"type": "json_object"},
                    temperature=0.7,
                )
                
                # Получаем ответ в формате JSON
                llm_output = json.loads(response.choices[0].message.content)
                thought = llm_output.get("thought", "")
                action = llm_output.get("action", {})
                
                print(f"🤔 МЫСЛЬ: {thought}")
                print(f"🎬 ДЕЙСТВИЕ: {json.dumps(action, indent=2, ensure_ascii=False)}")
                
                # Выполнение действия
                observation = self._execute_action(action)
                print(f"👀 НАБЛЮДЕНИЕ: {observation}\n")
                
                # Добавляем мысль и действие в историю
                self.history.append({"thought": thought, "action": action})
                
                # Проверяем, не хочет ли агент завершить работу
                if action.get("tool_name") == "finish":
                    print("\n" + "="*50)
                    print("✅ АГЕНТ ЗАВЕРШИЛ РАБОТУ.")
                    print(f"Ответ: {action.get('args', {}).get('answer')}")
                    return
                
                # Добавляем наблюдение в историю
                self.history.append({"observation": observation})
                
            except (json.JSONDecodeError, AttributeError) as e:
                print(f"❌ Ошибка парсинга ответа LLM: {e}")
                print(f"Ответ LLM: {response.choices[0].message.content}")
                # Даем агенту шанс исправиться
                observation = "Ошибка: твой ответ не был валидным JSON. Пожалуйста, строго следуй формату."
                self.history.append({"observation": observation})
        
        print("\n" + "="*50)
        print("⚠️ АГЕНТ ДОСТИГ ЛИМИТА ИТЕРАЦИЙ.")
    
    def _execute_action(self, action: dict) -> str:
        """Вызывает соответствующий инструмент."""
        tool_name = action.get("tool_name")
        args = action.get("args", {})
        
        if tool_name not in AVAILABLE_TOOLS:
            return f"Ошибка: Неизвестный инструмент '{tool_name}'. Доступные инструменты: {list(AVAILABLE_TOOLS.keys())}"
        
        tool_function = AVAILABLE_TOOLS[tool_name]
        try:
            return tool_function(**args)  # Важно: передаем аргументы как kwargs
        except TypeError as e:
            return f"Ошибка: Неверные аргументы для инструмента '{tool_name}'. {e}"
        except Exception as e:
            return f"Ошибка выполнения инструмента '{tool_name}': {e}"
    
    def _format_history(self) -> str:
        """Форматирует историю для передачи в промпт."""
        if not self.history:
            return "Пока не было сделано ни одного шага."
        
        formatted_history = ""
        # Собираем историю в пары "Действие-Наблюдение"
        for i, item in enumerate(self.history):
            if "action" in item:
                formatted_history += f"Шаг {i//2 + 1}:\n"
                formatted_history += f"  Мысль: {item.get('thought', 'N/A')}\n"
                formatted_history += f"  Действие: {json.dumps(item.get('action'), ensure_ascii=False)}\n"
            elif "observation" in item:
                formatted_history += f"  Наблюдение: {item.get('observation')}\n\n"
        
        return formatted_history

if __name__ == "__main__":
    agent_goal = "Проанализировать текущее состояние рынка автономных ИИ-агентов на 2025 год. Выделить 3 ключевых фреймворка, их основные преимущества и сохранить результат в файл 'ai_agents_market_2025.txt'."
    agent = AutonomousAgent(goal=agent_goal)
    agent.run()
```
